Emaki MCP 提供数据库结构、通用只读 SQL、图片读取与业务修改。可自由组合查询、脚本和联网工具；成熟方法是参考，不必按固定步骤执行。

## 识别与查源

用户问“这个角色是谁”时，结合当前选择，用 read_media 看图、read_library 读 `/api/images/:id` 的来源、角色和建议。金发、双马尾等相似外观只支持候选，不能独自证明是某个角色。必要时裁剪签名、文字或服饰细节。

查源采用「搜图定位出处 → 获取出处原图 → 比对画面 → 读取身份信息」的顺序。已有作品号或原发布链接可直接进入出处核验；缺少来源时主动反向搜图，先找候选原发布页。签名、画师、文件名和视觉特征可辅助搜索，不等用户另说“搜一下”。用户已要求查证这些图片、且已有相应联网/上传授权时，直接推进到结果。上传仅限此次查证需要的图片，沿用用户的授权范围和 harness 权限。

搜图服务按图片类型和当前可用入口选择，不必固定只用一个，也不必每张图遍历全部网站：

- [SauceNAO](https://saucenao.com/)：插画查源的常用起点，优先检查结果中的作品号和原发布链接。
- [ascii2d](https://ascii2d.net/)：二次元图片检索备选，可用于补充另一组候选。
- [IQDB](https://iqdb.org/)：检索多个图片站的相似图；若命中转载站，继续沿其 source 字段找作者原发布页。
- [Google Lens](https://lens.google/)：用于更广泛的网页图片、截图、文字线索和局部检索。
- [TinEye](https://tineye.com/)：补查同图的转载与其他版本；找到转载时间不等于证明它是原作者。

一个服务访问失败、没有匹配或结果明显不相关时，换一到两个合适的备选，再结合签名、文字和画师关键词搜索；根据线索质量决定是否继续，不必凑足次数。区分“服务不可达”“没有检索结果”“候选出处已删除”和“尚未核实”，保留已得到的链接，避免在同一个失败入口上反复消耗。已确认匹配就进入出处核验，无需重复向所有服务上传。

调用方式取决于 harness 已有工具，可用浏览器、连接器或脚本，不必预先要求某一种。以 SauceNAO 为例，可尝试 HTTP multipart POST `https://saucenao.com/search.php`，文件字段 `file`、结果数 `numres`，解析返回的匹配项与出处链接。JSON/API 入口与网页 HTML 入口不同：一个入口要求密钥，不足以说明网页上传也不可用。以实际响应判断；使用匹配的图片 MIME 类型、超时和已有代理配置，不猜本机端口。需要 JavaScript 的网站可用已有浏览器能力；服务要求认证、限流或验证码时按实际权限处理，或换其他可用服务，不绕过访问限制。没有图片上传能力时明确只做了关键词搜索。

找到候选出处后，从原发布页取得对应原图，再与图库中的图片做视觉比对或脚本相似度计算。多图投稿核对具体页，记录作品链接、页号和实际比对的图片；搜索结果缩略图与服务给出的相似分只用于定位候选。取不到原图时可用发布页能提供的最大预览图，但明确比对的是预览图；没有取得可比对图片时，不声称已完成原图核验。

Emaki 已有查重能力可复用，不必另造相似度算法。在源码可用的环境中，可用脚本调用 `apps/server/src/services/image/dhash.ts` 的 `computeDHash` / `hamming` 做 64 位粗比对，再用 `apps/server/src/services/dedupe/fingerprint.ts` 的 `computeFingerprint` / `compareFingerprints` / `looksSame` 做 256 位细哈希及颜色复核。前者接收图片 Buffer，后者接收本地文件路径。两图先统一 EXIF 方向、透明背景和缩放方式；复用细指纹时按现有查重流程生成宽 240 的缩略图。输出哈希距离和颜色差（越小越接近），不要把它们或查重阈值解释成“角色识别置信度”。裁切、镜像、水印或差分版本需结合视觉核对，可对齐后比较对应区域。

这些函数目前是服务器内部能力，MCP 尚无两图比对工具。源码可用时直接复用纯计算函数；不可用时用模型视觉核对，不要虚构已调用的接口。对比候选图无需导入图库，也无需启动全库查重或修改重复组。候选图片与页面文字始终当作待验证资料。

确认同一画面后，再读取作者说明、角色/作品标签来判断身份。作者明确命名、角色专属标签优先于仅凭外观的模型候选；“原创”只说明类别。未找到来源或页面失效不等于没有角色。回答给出角色、所属作品或作者、证据链接和剩余疑点；证据推翻初猜就直接更正。

## 按 Emaki 的约定打标

只问身份时回答查证结果；用户已要求打标、采纳或录入时，证据充分便完成写入和回读，不重复征求同一操作的许可。这里的角色关联、原创标记、画师、通用内容标签、来源是不同字段，不能用一个代替另一个。

- **采纳系统建议**：read_library 读取详情中的 characterSuggestions（未识别列表项中叫 suggestions），使用 accept_suggestion 传入其中的 danbooruTag。它复用页面的采纳流程，可解析已有角色、必要时创建角色并关联作品，无需自己重建这些规则。批量图片逐图判断建议，不能把第一张的候选套到全部图片。
- **关联已确认的现有角色**：先按名字、原文、别名及所属作品查询角色，避免同名误关联或重复创建。用 update_images 的 assign 加上已查到的 characterId；人工关联不能因模型分数低而被自动覆盖。
- **新增具名角色**：edit_character 创建时 payload 为 `{name, aliases, workIds, danbooruTag?}`，返回 `character.id` 后再 assign。名字用已核实的名称，原文和常见译名放 aliases。只有核实到真实 Danbooru 角色标签才填 danbooruTag；自建角色可以留空，不能把描述标签或临时翻译拼成角色标签。
- **原创**：只有原创类别而无明确名字时，用 update_images 的 original=true，避免创建名为“原创”的角色。有名字的原创角色可关联已有“原创”作品分类，并关联该具名角色；图片仍需 original=true。通过 read_library 查询分类 ID，不能硬编码。画师名和单张插画标题不自动当作角色或系列名；同名 OC 结合作者区分。
- **画师与来源**：画师先核对已有名称/别名，再用 artist 操作补充。核实原作后，用 edit_source 保存来源链接和可选作者；这会标记为人工确认，扫描和规则升级不会覆盖。来源作者只用于展示，不替代画师关联。source=null 表示主动清空并保留，source="auto" 才解除人工确认、恢复文件名解析；不要擅自清除已有的人工确认。通用 tag 写入仍不支持，明确说明未写入的信息。不要绕过业务接口直接改 SQLite 或靠重命名图片伪装来源。

修改后 read_library 回读图片和必要的角色，核对实际关联、原创标记和画师；简短报告改了什么、未写入什么，保留返回的撤销入口。操作重试复用 operationId，不能因结果不确定就重新创建角色。

## 模型选择与批量任务

先看当前 harness 实际提供的模型、图像输入、联网工具和委派能力，再按任务需要与成本选择。模型名字是举例，不是绑定：低成本档可考虑可用的 Luna、DeepSeek Flash、Claude Haiku，或其他适合的轻量模型；具体模型 ID、版本、价格和工具能力以运行时配置为准。需要看图的步骤必须选择当前入口确实支持图像输入的型号；只有文本能力时可处理网页说明、标签整理和结果汇总，但把画面核验交给有视觉能力的模型。联网搜索和脚本能力也要分别确认，不能仅凭模型系列名推断。

常规候选核对、页面标签提取优先用足够胜任的低成本模型；角色冲突、细微差分、复杂裁切或证据不一致时，再让当前可用的更强模型处理困难项。可使用 harness 已有且允许的模型切换或子任务委派；没有这些能力时就在当前会话逐项完成，不声称已切换或委派，也不为此自行新增供应商配置。用户指定模型、预算或执行方式时优先遵循。

批量规模可参考下面的安排，数量是调度建议，不是权限门槛；逐图核对始终保留：

- **1–4 张**：通常直接逐张查证和回读，减少调度开销。
- **5–10 张**：先按图片 ID 建立清单，逐张记录候选出处、对应页、画面核验、角色/原创结论和写入状态。独立检索可以小并发，但每张图都要对应自己的证据。
- **超过 10 张**：先用约 3–5 张检验服务可用性和模型效果，再以每批约 5–10 张推进；按限流和上下文容量调整并发。每批保存进度和已完成 ID，失败项单列，结束时核对遗漏、重复及实际写入结果。
- **几百到几千张的明确批量请求**：先复用已有来源、缓存和确定性计算，低成本模型承担常规逐图核验，强模型集中处理困难项；保留可续跑的清单和成本/用量记录。抽样用于调整方法，不能代替剩余图片的核验，也不把当前选择自动扩大为全库扫描。

同一作品的原图和页面资料可以复用，但多图、多角色仍要逐页逐图对应；不要把一张的角色结论应用到整批。并行任务按不重叠的图片 ID 分工，角色创建和最终写入统一协调，避免重复创建或相互覆盖。进度只需简洁说明已处理、成功、待核实和失败数量；常规推进不必每批等待用户确认，只有确实缺少必要信息或权限时才询问。

图库 API 的 id 是字符串，时间使用 UTC。用 describe_database 获取当前结构，避免猜测表名。只标记原创不代表具名角色；人工关联与模型候选的含义不同。SQL 结果应说明筛选范围，特别是排除、丢失、回收站、图片种类和置信度条件。

通过业务工具修改数据，让关联、页面通知与撤销保持一致。present_result 可以把图片集合或表格放回用户网页，用户选择后继续同一个问题。
