# 角色身份与常用名

先查图库条目、标准标签和所属作品。用 `read_library` 的 `/api/search?forAssignment=true&q=名字` 同时找现有角色和未建档建议。用角色详情核对条目和图片数，必要时用只读查询查看 `character_verified_forms`、`character_verified_names` 和 `danbooru_tag_redirects`。已有核验能回答当前问题时可以直接复用。需要判断图片里画的是谁时，结合[识别与查源](identify-and-source.md)。

**身份关系。** Danbooru 的标签可以分别描述本名、变身和特定形态。标签重定向可用于对齐同一标签；作品、重名、相似外观或标签共现适合筛选候选。要确认两个独立标签指向同一人，找明确连接两种身份的证据，例如制作方角色页、剧情、发行方资料或有可追溯引用的条目。可用 Danbooru wiki 和 Bangumi 的原名、别名与作品定位资料。露露卡的例子里，东映剧情直接写到她变身成 Cure Arcana，这比两个条目译名接近更能说明关系。

**常用名。** 先确认名字对应的是这个角色，再查目标语言里实际使用的名称。优先看授权游戏、出版社或播出方的用法；缺少译名时参考稳定的社区用法，并说明地区或版本差异。保留原文、旧译和常见异写供搜索。比如动画官方的完整姓名和中文条目都支持「古都吹寿子」，可以把旧显示名「寿久子」留作别名。用户已有名称偏好时沿用。

**让查证可复用。** 用户要求补正时，可用 `catalog_verify_character` 保存结果（查证内容放在参数 `input` 里）。`identity` 填变体或重复标签 `tag`、归属标签 `characterTag` 和关系 `form` 或 `same-character`。`name` 填角色标签 `tag` 和常用名 `name`。两者都写出直接出处 `sources`、说明出处证明什么的 `evidence` 和有用的 `aliases`。保留外部标签的原义。资料有冲突时，说明冲突和仍待核实的关系。

现有条目的合并走 `catalog_merge_character`（`id` 是被并掉的条目，`targetId` 是保留的）。如果还需要用户决定，用 `ask_user` 给出保留条目、拟迁移的图片数和依据。有明确操作指令时直接处理，回读角色、受影响的图片或搜索结果。核验和合并各有撤销入口；若两步都要撤销，先撤销合并。
