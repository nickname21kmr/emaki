# 元数据与业务流程

优先表达用户要修改的业务含义，再选择当前工具支持的操作。下列工具名和 payload 示例对应当前实现，参数以实际 MCP schema 为准。这里的角色关联、原创标记、画师、通用内容标签、来源是不同字段，不能用一个代替另一个。身份查证和写入可以连续完成；已有充分证据时无需重新搜图。

- **采纳系统建议**：read_library 读取详情中的 characterSuggestions（未识别列表项中叫 suggestions），使用 accept_suggestion 传入其中的 danbooruTag。它复用页面的采纳流程，可解析已有角色、必要时创建角色并关联作品，无需自己重建这些规则。批量图片逐图判断建议，不能把第一张的候选套到全部图片。
- **关联已确认的现有角色**：先按名字、原文、别名及所属作品查询角色，避免同名误关联或重复创建。用 update_images 的 assign 加上已查到的 characterId；人工关联不能因模型分数低而被自动覆盖。
- **新增具名角色**：edit_character 创建时 payload 为 `{name, aliases, workIds, danbooruTag?}`，返回 `character.id` 后再 assign。名字用已核实的名称，原文和常见译名放 aliases。只有核实到真实 Danbooru 角色标签才填 danbooruTag；自建角色可以留空，不能把描述标签或临时翻译拼成角色标签。
- **原创**：只有原创类别而无明确名字时，用 update_images 的 original=true，避免创建名为“原创”的角色。有名字的原创角色可关联已有“原创”作品分类，并关联该具名角色；图片仍需 original=true。通过 read_library 查询分类 ID，不能硬编码。画师名和单张插画标题不自动当作角色或系列名；同名 OC 结合作者区分。
- **画师与来源**：画师先核对已有名称/别名，再用 artist 操作补充。核实原作后，用 edit_source 保存来源链接和可选作者；这会标记为人工确认，扫描和规则升级不会覆盖。来源作者只用于展示，不替代画师关联。source=null 表示主动清空并保留，source="auto" 才解除人工确认、恢复文件名解析；已有人工确认可按用户要求再次编辑。通用 tag 写入仍不支持，用户确实要求写入这类标签时再说明可用的替代操作。写入使用业务接口，保持来源与真实发布信息一致。

修改后 read_library 回读图片和必要的角色，核对本次要求的字段；简短报告实际改动，保留返回的撤销入口。请求中有未完成的部分时说明并继续处理，不额外罗列无关字段。操作重试复用 operationId，结果不确定时先核对现有记录，避免重复创建角色。
