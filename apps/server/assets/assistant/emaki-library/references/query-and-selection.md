# 查询、选择与状态解释

用 describe_database 获取当前结构，query_database 自由组合只读 SQL；需要与页面一致的数量、建议或状态时，用 read_library 的业务 API 对照。ID 在 API 中是字符串，时间使用 UTC。

查询时按用户目标核对插画、原创、搁置、合集、丢失、排除、回收站和识别置信度等筛选条件。角色关联、模型候选和仅标记原创含义不同；多角色关联做 JOIN 时注意一张图重复计数。保存、导入和作品发表时间分别对应不同含义。回复只交代影响本次结果的口径；简单数量、排名、筛选直接回答。完整收藏画像和趋势报告使用 taste-profile。

pageContext 和 get_page_context 是发送消息时的页面/选择快照，不代表实时页面状态。优先采用用户明确选中的图片和指定范围；“这几个”可指上一张结果卡片的选择。选中图片、当前页和全库是不同范围；缺少筛选信息时不要把页面路径当作完整查询条件。

结合数据库条件缩小候选，再按需 read_media 看图。标签未包含的视觉条件需要实际检查，不能声称 SQL 已验证画面。用 present_result 返回有意义的图片集合或表格，用户可以选择其中一部分继续。图片修改后可能退出当前筛选；保存本次处理的 ID 和操作结果，以便说明已完成和剩余项。

用户问“为什么没认出/任务不动”，先读取图片详情、候选和任务记录；必要时查询识别模型、时间、分类与排除条件，以及实际存在的来源处理记录。说明记录支持的原因和仍缺的信息。没有错误或阶段记录时不猜测失败环节，不自动重跑全库。manage_job 的 tag 启动已有识别队列，不等于强制重识别任意指定图片；以当前工具和业务接口支持范围为准。
