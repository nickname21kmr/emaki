# 批量与成本

这份参考主要适用于需要逐图判断的任务。单次 SQL 聚合或已有确定性业务操作不因涉及图片多就需要 subagent；先复用现成能力。对需要独立查证的图片，按工作量、成本和恢复需求选择执行方式。

先看当前 harness 实际提供的模型、图像输入、联网工具和委派能力，再按任务需要与成本选择。模型名字是举例，不是绑定：低成本档可考虑可用的 Luna、DeepSeek Flash、Claude Haiku，或其他适合的轻量模型；具体模型 ID、版本、价格和工具能力以运行时配置为准。需要看图的步骤必须选择当前入口确实支持图像输入的型号；只有文本能力时可处理网页说明、标签整理和结果汇总，但把画面核验交给有视觉能力的模型。联网搜索和脚本能力也要分别确认，不能仅凭模型系列名推断。

常规候选核对、页面标签提取优先用足够胜任的低成本模型；角色冲突、细微差分、复杂裁切或证据不一致时，再让当前可用的更强模型处理困难项。可使用 harness 已有且允许的模型切换或子任务委派；没有这些能力时就在当前会话逐项完成，不声称已切换或委派，也不为此自行新增供应商配置。用户指定模型、预算或执行方式时优先遵循。

按任务规模决定由谁执行，以下数量只是起点，可根据单图难度、工具开销和 harness 能力调整：

- **小批量，通常 1–5 张**：主对话自己逐张完成搜图、出处核验和必要的写入回读。一般不必为了几张图启动 subagent，也不必额外切换模型。
- **约 6–10 张**：简单、已有出处的任务仍由主对话逐个做；如果多数图片需要独立搜图、多次联网或细致视觉核对，可以开始委派。是否委派主要看预计工作量，不按张数机械切换。
- **较大批量，通常超过 10 张**：harness 支持且允许时，优先派 subagent。可先启动 2–3 个，每个领取互不重叠的约 5–10 张图片，完成后再领取下一组；并发数服从可用槽位、网站限流和预算，不必每张图单开一个 agent。常规查证优先给当前可用且具有所需视觉/工具能力的低成本模型，例如 Luna、DeepSeek Flash 或 Claude Haiku。
- **几百到几千张的明确批量请求**：主对话维护可续跑的任务清单，先用少量图片确认流程可行，再持续分派给低成本 subagent；复用来源、缓存和确定性计算，把困难项集中交给更强模型。保存完成、失败和待核实状态及用量记录，中断后只补缺口。抽样用于验证方法，不能代替其余图片的逐图核验。

委派时给出图片 ID、任务目标、可用业务工具和需要遵循的本 skill，确保 subagent 能访问所需图片与来源。每个 subagent 逐图返回图片 ID、出处链接及页号、比对证据、角色/原创结论和未解决问题；不能只交一段整批总结。同一作品的原图与页面资料可复用，但多图、多角色仍需逐页逐图对应。

主对话负责分工、进度和最终结果：检查遗漏、重复及证据冲突，重点复核疑难项，不默认重做每个 subagent 的完整搜索。默认由 subagent 查证并提出修改，主对话协调角色创建、批量写入及回读，避免重复创建或相互覆盖；已有可靠分工和去重机制时也可委派写入，并收集实际结果与撤销信息。harness 不支持委派时退回主对话逐项处理，明确实际执行方式。

进度简洁说明已处理、成功、待核实和失败数量；常规推进不必每批等待用户确认，只有确实缺少必要信息或权限时才询问。不把当前选择自动扩大为全库扫描。
