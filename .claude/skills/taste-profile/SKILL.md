# 收藏偏好与变化

帮助用户理解这份收藏体现了什么、有哪些变化，以及证据能解释到哪一步。从用户的问题选择比较维度；收藏记录支持对这份样本的描述，不足以直接推断人的性格、动机或因果。

## 怎样判断

先确定值得回答的问题和可比较的范围。总体画像、时期变化、作品专题需要不同的参照；围绕用户目标选择已有分析能力，发现更有价值的线索时可以继续探索。普通查数量或筛选图片交给 emaki-library，不必生成完整报告。

趋势成立的前提是时间和统计口径可比。导入或备份时间可能影响时间轴，模型切换可能改变标签分布，少数大量收藏的角色可能主导张数比例。根据问题决定按图片、角色还是作品比较；对照不适合时，缩小结论范围比补充更多数字更有用。看不到明显差异、样本不足和数据覆盖不全都可以是结果。

优先复用有效的快照、抽样和已有产物。额外识别、下载或外部对照应解决一个明确的证据缺口；根据预期收益、成本和已授权范围决定是否运行。加载本技能本身不触发这些操作。

## 按需使用已有实现

- 需要生成、更新或恢复报告时，读 [运行说明](references/run-report.md)。使用现有计算脚本和 `template.html`，保持统计含义与报告结构一致。
- 解释指标、选择对照或评估趋势时，读 [解释方法](references/interpretation.md)。示例帮助判断，不预定结论。
- 撰写叙述并填入模板时，读 [story.json 格式](references/story-format.md)。只写数据支持且对用户有意义的发现。

技能目录中的脚本、模板和辅助数据共同构成报告能力。命令与字段以当前实现为准；遇到不支持的维度，先确认能力缺口，再说明可做的部分，不把未计算的数据写进报告。专题也应沿用现有方法，核对实际筛选范围。

## 交付到可用状态

报告生成后，核对关键数字、图表与叙述的一致性，并通过当前环境允许的方式检查展示效果。交付实际可访问的文件或入口，说明封面等资源对运行服务的依赖；文件已写出但尚未检查展示时，如实说明验证范围。浏览器拒绝某种访问方式时遵守限制，不通过替代通道绕过。

所有中间文件和报告保存在 Emaki 数据目录的 `profile/` 下；运行环境与会话输出位置见运行说明。保留可复用的数据与参数，使用户能追问、修订或续跑。任何结果、截图、角色列表都不要提交到仓库，也不要发布或上传。

## 本报告的分析边界

- 带儿童相关标签（loli、shota、child、aged_down 等）的图整张不参与任何统计，脚本已经处理，不要改掉。
- 不分析角色年龄。
- 私密部分（画面关系、尺度、部位、服装）默认不算。只有用户明确要求时才加 `--private`，报告里这一节的措辞保持客观。
- 访问 Danbooru 只用公开接口，请求之间留间隔。遇到 Cloudflare 验证页就停，不要重试、换头、绕过。
- 对照用的 Danbooru 图片只在本机打标签，打完就删。
