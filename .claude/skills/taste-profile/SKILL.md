# 个人喜好分析

从 Emaki 的图库数据里分析一个人的收图口味，输出 `data/profile/report.html`。

所有中间文件和报告都写在 Emaki 数据目录下的 `profile/`（默认 `data/profile/`，已被 git 忽略）。**任何结果、截图、角色列表都不要提交到仓库，也不要发布或上传。**

## 规则

- 带儿童相关标签（loli、shota、child、aged_down 等）的图整张不参与任何统计，脚本已经处理，不要改掉。
- 不分析角色年龄。
- 私密部分（画面关系、尺度、部位、服装）默认不算。只有用户明确要求时才加 `--private`，报告里这一节的措辞保持客观。
- 访问 Danbooru 只用公开接口，请求之间留间隔。遇到 Cloudflare 验证页就停，不要重试、换头、绕过。
- 对照用的 Danbooru 图片只在本机打标签，打完就删。

## 步骤

所有命令都在 Emaki 仓库根目录运行。数据目录不是默认的 `data/` 时，每条命令都加 `--data <目录>`。

1. **快照**：`node .claude/skills/taste-profile/scripts/snapshot.mjs`
   之后只读快照，不碰正在用的库。

2. **看时间是否可信**：用 sqlite 看各个 `library_roots` 下图片的 `modified_at` 分布。
   - 有的备份在复制时把修改时间全改成了复制那天，这种文件夹的时间不能用。
   - 把它们的 id 记下来，后面每一步都加 `--undated-roots 1,3`，这些图会归到「更早」。
   - 文件名里带时间戳的（`2023_01_12_21_51_57_IMG_….JPG`、`Image_<毫秒>`）不受影响。

3. **统一标签口径**：如果库里同时有 WD 和 PixAI 打的标签（`images.tagger_model`），运行：
   `node --import tsx .claude/skills/taste-profile/scripts/wd-sample.mts --undated-roots …`
   - 它把非 WD 的图每个时期抽 600 张，用 WD 重打。
   - 重跑是增量的，只补缺的部分。
   - 不做这一步的话，"换模型"会被误读成"口味变了"。

4. **Danbooru 对照**（可选，但推荐，否则只能和全站二十年的人工标签比）：
   - `node .claude/skills/taste-profile/scripts/baseline.mjs --undated-roots …`
     - 默认抽三组，每组约 1000 张：`recent`（同时期全站）、`cn`（中文平台来源，也就是中文圈画师）、`works`（用户收得最多的作品）。
     - 会下载约 400 MB，用完删除。
   - `node --import tsx .claude/skills/taste-profile/scripts/baseline-tag.mts`

5. **算数字**：`node .claude/skills/taste-profile/scripts/analyze.mjs --undated-roots … [--private]`
   - 输出 `data.json`。
   - 先检查控制台的统计单元数量，应该接近插画数；还要看 `data.json` 里的 `uncovered` 是否为空，不为空就回到第 3 步补抽样。

6. **写文字**：读 `data.json`，写 `data/profile/story.json`（格式见下）。这一步决定报告有没有价值，要求见「怎么写」。

7. **生成报告**：`node .claude/skills/taste-profile/scripts/report.mjs`，然后用浏览器打开 `report.html` 检查。
   - 角色封面从 `http://127.0.0.1:5174` 读取，Emaki 要开着。
   - 检查有没有空白的图表，或者 NaN。

## 怎么读数字（容易出错的地方）

- **只和全站比会误判**：全站二十年的标签里早年的东方、Fate 老图很多，人工标签和模型标签的习惯也不一样。比如"白发偏爱"，换成同时期、同模型的对照后可能就消失了。结论要以对照组为准：`looks.hair[].vs`、`camera`、`vsCn`。
- **中文圈只在同一尺度内比**：中文平台有审查，那边公开的图几乎没有较敏感以上。脚本已经只用全年龄 / 轻微去比外观和镜头。也不要把"中文圈画师画什么"说成"中国用户喜欢什么"，它是最接近的参照，但不等同。
- **按张数和按角色是两回事**：几个存了上千张的角色会主导张数比例，所以"按张数最爱的发色"不等于"按角色最爱的发色"。`hairByCharacter` 是每个角色只算一次的版本；`conv`（出现过的角色里存到 20 张以上的比例）能解释"为什么觉得自己存了很多某种发色"。
- **性格要扣掉人气**：按张数，"冷面寡言"可能排第一，但只是因为这类角色本来就火。看 `popularity.archetypes` 的 ratio 和区间（lo–hi）：区间整体大于 1 才算真的偏爱。
  - 性格原型来自 `archetypes.json`，是人工对照表，只覆盖常见角色；用户的主力作品里有新角色时，可以先补进表里再算。
  - 不认识的角色不要编性格，只描述数据，比如"存的图里六成在笑"。
- 扣人气时不算男性角色（图里六成以上画了男性的角色），否则「跳过的」会被男性角色占满。
- **`popularity.hidden` / `skipped`** 往往最有意思：同一部作品里谁被超配、谁被跳过（例如同一部番里偏向另一支乐队）。描述时说清楚人气用的是 Danbooru 帖子数，偏日本和欧美。
- **有些数据会说"没有差别"，这本身就是结论**：几点存图、一轮连续存图里尺度变不变（`rhythm.hourNsfw`、`sessionPos`）。如果没有差别，就写"尺度是稳定的口味，不随深夜或情绪变化"。
- **`arcs`**：入坑到高峰的天数和高峰集中度。数据刚开始就在收的角色已经排除了，但时间太短的库看不出慢热还是快热。
- **`resave`**：隔很久又存了一次的同一张图，代表"最稳定的吸引力"。它多出来的标签比整体偏爱更可信。
- **样本量**：样本少的时期（几百张）、对照组每组约 700 张（只算女性角色后），小于 2 个百分点的差别不要写成结论。

## 怎么写 story.json

简体中文，写得平实、具体，每句话都尽量带数字或例子。不要营销腔，不要"你是一个……的人"这类空话，也不要把相关说成因果。先写出乎意料的结论，再写确认性的。每个字段都可以省略，没有文字的那一节只显示图表。

```json
{
  "date": "2026-09-29",
  "title": "一句话标题",
  "lead": "两三句：用了什么数据、和谁比、有哪些结论和直觉相反（可以用 <b>）",
  "persona": "一段画像：喜欢什么样的角色、怎么看她、怎么收图",
  "tags": [["发色", "金 / 黑"], ["性格", "高傲大小姐"]],
  "findings": [{ "h": "短标题", "b": "带数字的一两句" }],
  "sections": {
    "rhythm": { "text": "", "points": [] },
    "works": { "text": "", "points": [] },
    "looks": { "text": "", "points": [], "note": "" },
    "persona": { "text": "", "points": [], "note": "" },
    "camera": { "text": "", "points": [] },
    "loves": { "text": "", "points": [] },
    "cn": { "text": "", "points": [], "note": "" },
    "shift": { "text": "", "points": [] },
    "arcs": { "text": "", "points": [] },
    "most": { "text": "" },
    "private": { "text": "", "points": [] },
    "method": { "note": "" }
  },
  "mostIds": [123, 456],
  "summary": ["<h3>小标题</h3><p>一段</p>"]
}
```

- `findings` 写 6–9 条，每条要么是意料之外的，要么是能纠正直觉的。
- `mostIds` 可选：从 `data.mostYou` 里挑，先通过 Emaki 看一眼缩略图（`/api/images/<id>/thumb?w=480`），去掉截图、照片这类误分类的。

## 可以继续做的

- **专题**：只看某一两部作品（比如两个游戏），在同作品里扣人气比角色，再和 Danbooru 上同一个游戏的图比画面。方法同上，把对照抽样限定在这部作品的标签里。
- **按画像画图**：本机有 ComfyUI 和动漫模型的话，可以把画像里最确定的几项（发色、发型、服装、姿势、镜头）写成提示词，生成虚构的成年角色。用户买过画集或常收的画师可以作为画风参考。
