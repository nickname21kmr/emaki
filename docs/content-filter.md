# 可选的本地图片分类（实验分支）

目标是把照片、文字、截图、表情包等从“插画”中排除。使用 Qwen3.5-4B Q4_K_M，已有 Pixiv 来源标记的图片优先保留。默认关闭；不把权重放进安装包、不自动下载，也不增加 npm 推理依赖。

## 判定与运行顺序

- 用户手动分类、按漫画导入的文件夹、GIF 动图保持各自规则。
- 数据库的 `source_site='pixiv'` 优先保留为插画，不读图、不运行 4B。这个标记来自现有来源解析，包括文件名解析；本步骤不访问 Pixiv 网页、也不要求页面仍存在。它不是对图片媒介的网页认证，因此 Pixiv 上的截图等也可能被保留。
- 其余图片先执行原有轻量规则。只把已打标签、仍归插画、可见且所属图库启用、尚无有效复核的图片送给 4B。原来已经归照片、截图等的图片不再重复推理。
- 角色识别完成后自动排“图片分类”；重启扫描后也可接着处理。任务与角色/画师识别共用 GPU 队列，加载 4B 前关闭角色模型的空闲缓存。更高优先级任务到来时逐张让出。
- 只接受七个枚举：illustration / photo / screenshot / text / meme / comic / uncertain。uncertain 保留原分类。输出不包含角色、内容题材或自由文本解释。

## 开启

准备 [llama.cpp](https://github.com/ggml-org/llama.cpp/releases/tag/b11718) 运行文件及其依赖 DLL。Windows + CUDA 的 b11718 已在 RTX 5070 Ti 测试；其他平台和显卡后端尚未验证。不要只复制 exe 丢下其 DLL。

从固定版本的 [Unsloth GGUF 仓库](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/tree/e87f176479d0855a907a41277aca2f8ee7a09523) 获取：

| 文件 | 字节 | SHA-256 |
| --- | ---: | --- |
| Qwen3.5-4B-Q4_K_M.gguf | 2740937888 | 00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4 |
| mmproj-BF16.gguf | 675569344 | 302b92d565080b9cc0281186979ae75a7429ec23d14f6f7607a035539b21f3a6 |

在仓库根目录的 `.env` 设置，路径可为绝对路径：

```dotenv
EMAKI_CONTENT_FILTER=1
EMAKI_LLAMA_SERVER=./data/models/llama.cpp/llama-server.exe
EMAKI_CONTENT_MODEL=./data/models/Qwen3.5-4B-Q4_K_M.gguf
EMAKI_CONTENT_PROJECTOR=./data/models/mmproj-BF16.gguf
```

重启后，在设置页的后台任务菜单运行“图片分类”。文件不存在时不会自动排任务；手动运行会提示缺少配置。模型文件存在但损坏时，校验会使任务失败。关闭开关并重启后停止后续推理；已经保存的自动分类仍有效。

Pixiv 来源优先是轻量分类规则，关闭 4B 开关后也有效。此分支的数据库迁移与此前本地 v1 视觉复核列兼容，不依赖旧 CLIP 分类头或照片模型。

## 资源、缓存和失败处理

模型与视觉组件合计约 3.42 GB；本机试验新增显存峰值约 4 GB。模型只在有候选图片的任务中启动，完成、取消或让出时立即关闭。任务期间它仍然是一套较重的可选模型，未实现蒸馏或进一步压缩。

原图先校验 SHA-256，再自动转正、白底处理透明、按比例缩至最长边 1024。只把图像送往自建的回环地址服务，使用随机端口和随机 API 密钥。服务有独立监管子进程，父进程断开时关闭推理进程。

每张结果保存在 `images.content_review`，绑定文件哈希和固定模型/提示词配置版本。重新打角色标签或重算分类不会丢失；文件内容变化或配置版本升级后失效。v1 的既有视觉复核继续兼容，v2 的新记录不伪造置信度、不占用手动分类字段。

写回前再次检查数据库中的内容哈希、来源、手动分类、路径、所属图库状态和打标时间。推理期间发生删除、移动或手动修改时丢弃过期结果。任务逐张提交，中途取消保留已完成进度；未完成图片下次继续。

解码失败、哈希不符、超出 64 MiB / 1 亿像素限制的单张图片保留原分类并记录错误，自动续跑不反复读坏文件。手动运行会清除此配置的错误缓存，再尝试。模型启动失败、请求超时、非法输出会使任务失败并暂停本次进程内的自动重试；需手动重试或重启。取消同样暂停自动续跑。

推理不在 HTTP 主进程执行。最长加载等待 180 秒，单张等待 90 秒；启动会额外用矛盾提示词验证 JSON Schema 是否真正约束了解码。每 20 张通知界面，结束后再更新合集统计。

## 验证范围

开发比较使用同一批 264 张图片、固定提示词和关闭思考的设置。4B 原先的两张“误排”后来由用户确认为动画截图，属于参考标签修正；原试验记录保留不改。该比较不是独立盲测，也不能解释为全库零误伤。

接入后另用临时数据库和真实 CUDA 推理验证了 17 个回归样本：1 个 Pixiv 来源跳过推理、其余 16 张运行 4B，14 张非插画被排除，3 张插画保留；重复运行没有再推理，重新计算分类保留结果。验证未修改实际图库。

真实进程测试还验证了文件哈希不符、请求取消、监管进程与父进程断开时的清理；结束后没有遗留 llama-server 进程。

自动化测试覆盖默认关闭、Pixiv 绕过、手动/漫画/GIF 优先、缓存与重打标签、并发修改、损坏文件、取消、失败暂停、队列让出和非法输出。模型错误分类仍可通过现有手动分类修正。
